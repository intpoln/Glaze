3. **high — открытый Material Editor способен вернуть старый граф, сохранив новую версию.**  
   [GlazeMaster.cpp:611](C:/Users/intpo/Desktop/Glaze/GlazeLab/Plugins/Glaze/Source/GlazeEditor/Private/GlazeMaster.cpp:611)

   Material Editor редактирует копию мастера. Уведомления от `Create/Delete/LayoutMaterialExpressions` вызывают только `NotifyExternalMaterialChange()`, который здесь обновляет статистику. Копия графа не перечитывается. При Apply редактор копирует её обратно и сохраняет metadata оригинала.

   **Воспроизведение:** открыть мастер версии 4 и сделать несохранённую правку → вызвать Glaze, получив граф версии 5 → нажать Apply в старом редакторе → старый граф перезаписывает новый, но `GlazeMasterVersion` остаётся 5. Следующий `EnsureMaster()` уже пропускает восстановление.

   **Исправление:** после пересборки явно обновить редактор через `RefreshMaterialEditor()`. Для редактора с несохранёнными правками нужен явный сценарий разрешения конфликта: эта функция может отбросить их.

6. **medium — Local triplanar использует несовместимые пространства позиции и нормали.**  
   [GlazeMaster.cpp:397](C:/Users/intpo/Desktop/Glaze/GlazeLab/Plugins/Glaze/Source/GlazeEditor/Private/GlazeMaster.cpp:397)

   `LocalPosition` по умолчанию возвращает **Instance space**, а `Transform(World → Local)` использует пространство **Primitive/Component**. На ISM/HISM это разные системы координат.

   **Воспроизведение:** ISM-компонент без поворота, два одинаковых куба; второй инстанс повернуть на 90° вокруг Y → включить текстурный Detail в Local space → координаты второго куба остаются локальными относительно инстанса, а веса проекций ориентируются относительно компонента.    Дополнительно при неравномерном масштабе обычное преобразование вектора через `WorldToLocal` не восстанавливает локальную нормаль: для нормали требуется соответствующее преобразование обратной транспонированной матрицей.

**Остальная математика и компиляция**

- При положительном tiling UV-поворот и обратный поворот XY нормали согласованы. Flip Green корректно меняет знак уже декодированной Y-компоненты перед вращением.
- Packed-каналы используют RGBA и четырёхкомпонентный dot; one-hot маска корректно выбирает канал. Общий `PackedTex` позволяет переиспользовать одну выборку.
- Порядок grayscale remap корректен: invert → contrast/bias → saturate → Min/Max.
- Формула surface-gradient bump и whiteout-бленд структурно корректны. Дополнительных выборок высоты они не требуют.
- Статические свитчи выбирают одну ветку и в legacy translator, и в MIR. Неактивные ветки не попадают в исполняемый шейдер. Предварительный обход VertexInterpolator возможен при трансляции, но runtime-интерполяторы выделяются по фактическому использованию.
- Повторные параметры Detail Map и переключатели пространств имеют одинаковые значения по умолчанию; самостоятельного функционального конфликта не нашёл.
- LWC сохраняется до процедурного Noise: UE имеет перегрузку для double-float. Текстурные выборки также обрабатывают LWC UV через address math до преобразования в float.
- Sampler types и создаваемые linear defaults согласованы при штатных настройках текстур. Opacity/dither и emissive соответствуют текущему контракту; emissive «из Base Color Texture» намеренно берёт исходную текстуру.
- Граф содержит стандартные типы UE и зависимости `/Game`/`Engine`; зависимостей от runtime-классов Glaze в этих файлах не обнаружено. Перенос и cook без плагина здесь не проверялись.

**Стоимость шейдера**

Для BC + Normal + ORM ожидаемое число логических texture lookups:

| Включённые функции | Выборки |
|---|---:|
| Базовый материал | 3 |
| Detail texture, UV | 4 |
| Detail texture, triplanar | 6 |
| Procedural Detail | 7 |
| Только Macro | 6 |
| Triplanar Detail + Macro | 9 |
| Procedural Detail + Macro | 10 |

Отдельные emissive/opacity-карты добавляют по выборке; использование BC или packed переиспользует существующую. Таблица исключает dither, освещение и дополнительные проходы.

«Процедурный» Fast Gradient здесь использует текстуру движка: четыре выборки для Detail и три для Macro. Заголовок UE оценивает примерно **16 инструкций на октаву**: около 64 для Detail и 48 для Macro, сверх остального графа. Точное число зависит от платформы и компилятора. UE также помечает этот режим как нежелательный для bump; его визуальное качество стоит проверить отдельно.

**Память / GC**

Подтверждённое лишнее удержание памяти — находка №1: оставшиеся expressions и их ссылки сохраняются в мастере и не освобождаются GC. Это также увеличивает размер ассета.

Других подтверждённых утечек, долгоживущих незащищённых UObject-указателей или делегатов без отписки в этих двух файлах не нашёл. `FGraph`/`FPin` живут только во время синхронного построения; expressions зарегистрированы в коллекции материала. Пики памяти при компиляции возможны из-за пяти заранее включённых Usage flags и пермутаций MI, но их величина не измерена.

**UX-предложения, по пользе**

1. Показывать результат сохранения мастера и зависимостей; при ошибке не сообщать об успешном создании.
2. Согласовать обновление мастера с открытыми редакторами, явно обозначая судьбу несохранённых правок.
3. Показывать краткую стоимость Noise: UV texture — 1 выборка, triplanar — 3, procedural — 4, Macro — ещё 3.
4. Отделить включение Bump от Detail; нулевая сила должна давать дешёвую ветку.
